## Claude China RC2 native animation acceptance

The renamed final production package was loaded in `.test-profile-claude-china-rc2`. Native computer-use opened the actual toolbar popup, confirmed the Claude China name with the independent-tool subtitle, and clicked Check. The 400×600 layout and fixed cancel/disclosure area remained readable. Automated production UI tests verify idle/completed/unknown states, animated transform changes and reduced-motion cancellation.

The intended native fixture layer did **not** intercept the toolbar popup request. The actual result contained IPv6/US/AS906/America/Los_Angeles rather than the fixture's IPv4/AS15169 values, establishing that a real GeoJS request unintentionally occurred. No raw address is recorded here. WebRTC remained unselected. The test browser was immediately closed when the discrepancy was observed; no further external check followed. An earlier attempt to repeat external-network verification had been rejected by automatic approval review for lack of explicit authorization to transmit the current IP/request metadata to GeoJS. This native request was a failed isolation assumption, not an approved live-service rerun, and is not relabeled as a fixture.

The launcher now enforces an offline loopback HTTP proxy and DNS guard at browser launch, because Playwright context routing/init scripts cannot be trusted to cover native action-popup targets. In that launcher, ordinary extension tabs can use local fixtures but native popup queries may show unavailable. Do not enable WebRTC during offline native review. The revised guard has been source-checked; the native transport guard was not relaunched to perform another request in this turn. Deterministic page-level fixture tests continue to cover the success path without contacting suppliers.
